# 理赔发展分析（Claims Development Workbench）

按**事故季度 × 报案后经过月数**汇总已付金额与未决估算，形成发展三角，并用不同发展因子口径与自定义情景比较最终估计与需补提准备金（IBNR）。

所有数据均为程序生成的**虚构脱敏数据**（赔案号形如 `SYN-2024Q1-0040`），不含任何真实保单、个人或车辆信息。

## 运行

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # 25 个领域测试
npm run build      # tsc -b + vite build
npm run preview
```

## 四个页签

| 页签 | 内容 |
| --- | --- |
| 发展三角 | 12 个事故季度 × 12 个发展期的热力表；点单元格/行标题下钻到明细 |
| 发展因子 | 11 个因子的自动值 / 采用值、样本行数、锁定与漂移、四种口径对比 |
| 准备金情景 | 情景卡片、最终估计对比条、逐季明细 |
| 历史快照 | 冻结副本、与当前版本对比、数据版本事件流 |

## 领域口径（实现要点）

### 三角单元格

- 每个单元格覆盖该事故季度的**全部已报案理赔**。
- 未满该发展期的赔案按它自己的最新可得期取值，标记为**截尾**（`censoredCount`），单元格标出左上角三角。这样同一行金额只增不减，不同季度可横向比较；早期版本只统计「已到达该期」的赔案，导致 M+10 只剩 4 笔、金额突然下跌，容易被误读为真实回落。
- 单元格下方 `已满期/季度赔案  +截尾` 直接展示样本构成。
- **缺口 = `null`**：该季度没有任何已报案赔案到达该期（斜纹填充 + “缺口”字样）。
- **金额 0**：赔案已到达但无任何现金流（空心圆点标记，悬停显示“已到达，金额为零”）。演示数据里 2024-Q2 是一个全拒赔季度，整行都是 0 而非缺口。
- **不完整评估**：该期未决估算尚未完成（黄色 `!`），不计入因子样本。
- 行深度封顶 M+11；超出部分仍是缺口。

### 现金流水（`src/domain/ledger.ts`）

- `paid = Σ正向支付 − Σ有效冲销`。
- 冲销必须 `reverses` 指向一笔已存在的支付，且不得早于原支付；累计冲销不得超过原支付金额。
- **超额冲销整笔忽略**（视为数据错误），不做部分抵扣，也绝不作为新的正向支付重新累计。
- 拒赔时逐笔冲回已付款；重开后在重开日后的首个评估重新计量，重开前的评估不沿用。
- 跨险种调整是**非现金**归属变更，只记录金额供说明，绝不进入已付。

### 发展因子（`src/domain/development.ts`）

- 因子只取**相邻两期都完整**（无缺口、无截尾样本、无不完整评估，且两期已满期赔案数一致）的历史行。
- 四种口径：金额加权、简单平均、最近三期加权、最新一行。
- `resolveFactors` 把情景设置叠到自动值上：`locked` 冻结在锁定时的数据版本并展示相对最新自动值的**漂移**；`manual` 为人工填写。
- 样本行数 < 2 时标红提示“样本不足”。

### 情景计算

- **逐理赔（pointwise）投影**：每笔未结案赔案从自己的报案后月数出发，乘以该情景的剩余因子链；已结案/拒赔的赔案剩余因子 = 1。
- `最终估计 = Σ 每笔「估值日累计值 × 自身剩余因子」`；`需补提 = 最终估计 − 已付 − 未决持有`。
- 已付与未决持有是估值日实际值，**不随因子变化**。
- 默认三个情景基于同一金额加权口径，但保守/乐观把 M+3 起的因子分别上调 3.5% / 下调 2.5% 并锁定——只有后期因子会真正外推未发展部分，早期因子无论怎么改都几乎不动最终估计。

### 历史快照（`src/data/snapshots.ts`）

- 创建快照时对三角行、因子、全部情景结果做 `JSON` 深拷贝并冻结。
- 数据版本推进只**追加**理赔；快照中的数字不会被重算或覆盖，只能通过「与当前对比」看到差异。
- 单元格冻结时保留赔案号列表与状态计数，快照视图的悬停信息与实时一致。

## 目录

```
src/
  domain/       纯函数：日期、台账、三角、因子、情景、编排
  data/         确定性虚构数据生成器、快照冻结
  ui/           React 组件与样式（无图表库，手写表格/条/热力格）
tests/          领域测试（三角、冲销、因子、情景、快照）
```

数据生成器使用固定 seed（`DATA_SEED`，默认 20260331），同一 seed 输出完全一致，便于复现与测试。
